# Viet Template 1.0 Readiness Gap Analysis & Surface Audit

This document provides an exhaustive gap analysis evaluating Viet Template against the **Definition of Done for 1.0.0 General Availability (GA)**. It audits all fifteen architectural areas, details the 105 stable public types versus 259 accidental public types across 5 baselines, outlines the encapsulation remediation roadmap, and provides an authoritative release recommendation.

---

## 1. Executive Summary & 1.0 Readiness Verdict

> [!IMPORTANT]
> **Verdict: NOT YET READY FOR IMMEDIATE 1.0.0 GA.**
>
> While Viet Template has achieved 100% VTL language compatibility (80/80 TCK features), decisive performance wins over Apache Velocity 2.4.1 (1.3x–5.3x throughput), enterprise-grade security sandboxing, full GraalVM/Spring Boot 4 native support, and first-class Quarkus 3 integration, **one critical architectural blocker remains for 1.0.0 GA**:
>
> **The Public Surface Exposure (259 `PUBLIC_BUT_INTERNAL_ACCIDENT` types)**: Under Semantic Versioning 2.0.0, releasing 1.0.0 commits the project to permanent binary and source backwards compatibility for all exported public types. Releasing 1.0.0 with 259 exposed internal implementation types would permanently compromise the project's ability to refactor internals without breaking SemVer.

### Recommended Release Sequence
1. **0.2.3 (Immediate Stabilization & Adoption Release)**:
   - Ship the complete documentation suite, Apache Velocity migration guide, comprehensive diagnostic error catalog, plain Java examples, first-class Quarkus extension, and build tooling refinements.
   - Maintain the existing baseline while enabling external Java teams to evaluate and migrate to Viet Template.
2. **0.3.0 (Internal Surface Encapsulation Milestone)**:
   - Encapsulate the 259 accidental public types using package-private visibility reductions, package relocation (`*.internal.*`), and formal internal SPI boundaries.
   - Re-baseline the public API surface strictly to the 105 verified `STABLE_API` and `STABLE_SPI` types.
3. **1.0.0 GA (General Availability)**:
   - Lock permanent binary backwards compatibility, certified by real-world production adopter validation.

The 119 stable types (94 `STABLE_API` + 25 `STABLE_SPI`) represent the intended permanent API/SPI contract of Viet Template across 5 baseline definitions:
- **Core Baseline (`1.0-core-public-api.txt` — 82 types: 81 API + 1 SPI)**:
  - Core engine entry points: `TemplateEngine`, `Template`, `CompiledTemplate`, `TemplateId`, `TemplateSource`.
  - Repository & loading: `TemplateRepository`, `ClasspathTemplateRepository`, `FileTemplateRepository`, `StringTemplateRepository`.
  - Context & Configuration: `RenderContext`, `RenderRequest`, `TemplateSuffixConfiguration`, `UndefinedReferencePolicy`.
  - Security API: `MemberAccessPolicy`, `RenderBudget`, `TemplateSecurityException`.
  - SPI: `RenderContextContributor`.

  - API: `TemplateAotCompiler`, `AotCompilationResult`, `AotCompilerOptions`.
  - SPI: `AotSourceProvider`, `AotClassConsumer`, `AotDiagnosticListener`.
- **Spring Baseline (`1.0-spring-public-api.txt` — 8 types: 7 API + 1 SPI)**:
  - API: `VietTemplateView`, `VietTemplateViewResolver`, `VietTemplateProperties`, `VietTemplateAutoConfiguration`.
  - SPI: `VietTemplateEngineCustomizer`.

  - SPI: `QuarkusSecurityRenderContextContributor`.

### 3.2 Accidental Public Types (Post-0.3.0-M3.5: 85 Types Remaining)
The original 259 types classified as `PUBLIC_BUT_INTERNAL_ACCIDENT` were mechanically audited and categorized in `config/api-baseline/accidental-public-types-inventory.json`. In milestone **0.3.0-M1**, 34 Category-A types were demoted to package-private. In **0.3.0-M2**, 49 Category-B types were relocated to `*.internal.*`. In **0.3.0-M3.3**, 56 Category-C1 types were reclassified to `INTERNAL_CROSS_MODULE`, 4 framework/build entrypoints were formally typed, 1 ABI type classified, and 1 C7 type (`ModelSchema$Builder`) was package-private contained. In **0.3.0-M3.4**, 6 interpreter contracts were formalized. In **0.3.0-M3.5**, 55 intra-module types were classified as `INTERNAL_CROSS_PACKAGE`, 3 benchmark-only types as `BENCHMARK_SUPPORT_INTERNAL`, and the remaining 85 types registered in `config/architecture/public-surface-debt-registry.json`:
1. **Category A — Package-Private (34 Types Demoted in 0.3.0-M1, 0 Remaining)**
2. **Category B — Internal Package (49 Types Relocated to `*.internal.*` in 0.3.0-M2, 0 Un-internalized Remaining)**
3. **Category C1 — INTERNAL_CROSS_MODULE (56 Production Contracts Verified in 0.3.0-M3.5)**:
   - 48 types from `language-vtl → vtl-interpreter` (AST, IR, Lexer, Semantics, Optimization).
   - 7 types from `runtime → vtl-interpreter` (linker internals: `AccessLink`, `CallSiteRegistry`, `DynamicCallSite$State`, `DynamicLinker`, `LinkerStatistics`, `MemberKey`, `MemberOperation`).
   - 1 type across `runtime → spring` and `runtime → quarkus` (`NonClosingOutputStream`).
4. **INTERNAL_CROSS_PACKAGE (55 Types Classified in 0.3.0-M3.5)**:
   - Deliberate intra-module package boundaries across `vtl.internal.compiler.*`, `vtl.internal.engine.*`, `vtl.internal.interpreter.*`, `vtl.engine.cache.*`, `vtl.engine.dependency.*`, `language.vtl.internal.*`, and `runtime.linker.*`. Not architectural debt.
5. **BENCHMARK_SUPPORT_INTERNAL (3 Types Classified in 0.3.0-M3.5)**:
   - `EvaluationValue$State`, `ExecutionFrame`, `ForeachMetadata` (vtl.interpreter) — consumed only by the unpublished JMH benchmark suite.
6. **Debt Registry (85 Types Remaining as PUBLIC_BUT_INTERNAL_ACCIDENT + 3 Non-Prod Contracts = 88 Total Debt Types)**:
   - AST concrete nodes (41 types): sealed hierarchy language topology, target M22. Candidate remedies: module consolidation, ownership restructuring, narrow internal compiler facade, representation relocation, or retained intentional cross-module contract.
   - IR concrete implementations (33 types): target M22. Candidate remedies: same as AST concrete nodes.
   - Semantics types (11 types): target M22.
   - Remaining interpreter non-prod contracts (`EvaluationValue`, `ExecutionContext`, `EngineInterpreterBridge`, 3 types): classified `INTERNAL_CROSS_MODULE`, target M4.5 benchmark relocation.

## 4. Remediation Strategy for 1.0 GA (Milestone 0.3.0)

To resolve the 1.0 surface blocker without breaking plugin compilation or runtime bytecode dispatch, Viet Template executes an encapsulation and convergence plan:

### Step 1: Package-Private Visibility Consolidation (0.3.0-M1 — COMPLETE)
Demoted 34 validated intra-package helpers and internal utilities to package-private visibility in sub-milestone `0.3.0-M1`. Accidental public surface reduced to 225 types.

### Step 2: Package Relocation to `*.internal.*` (0.3.0-M2 — COMPLETE: 49 Types Relocated)
Relocated 49 intra-module internal types to subpackages containing `.internal.` across `viet-template-language-vtl` and `viet-template-vtl-interpreter`. Reclassified 17 types to Category C. Migration reference published in `docs/migration/0.3.0-internal-package-moves.md`.

### Step 3: Public Surface Role Classification & Entrypoint Taxonomy (0.3.0-M3.3 — COMPLETE)
Established nine-category taxonomy (ADR-0017). Formally classified 56 cross-module internal production contracts as `INTERNAL_CROSS_MODULE`, 4 framework entrypoints, 4 build-tool entrypoints, and 1 generated ABI type. Contained `ModelSchema$Builder` to package-private. Zero signature leaks.

### Step 4: vtl-interpreter Contract Formalization (0.3.0-M3.4 — COMPLETE)
Formalized 6 interpreter contract types and added `ExecutionTier` API.

### Step 5: Final Architecture Convergence & Debt Registry (0.3.0-M3.5 — COMPLETE)
Classified 55 `INTERNAL_CROSS_PACKAGE` types, 3 `BENCHMARK_SUPPORT_INTERNAL` types, established consumer scope annotations (`MAIN`/`TEST`/`BENCHMARK`) on all 62 contracts, created `public-surface-debt-registry.json` tracking all 85 remaining debt types, clarified JPMS vs package consolidation, and approved `BEGIN_RUNTIME_ARCHITECTURE`.

### Step 6: JPMS Qualified Exports Decision Gate (M22 — DEFERRED)
JPMS evaluation is deferred to M22 when the physical module boundary between `language-vtl` and `vtl-interpreter` is re-evaluated. Note that JPMS does not reduce Java `public` visibility on the classpath; package-private demotion and package consolidation provide the primary line of defense.

## 5. Decision Matrix: Release 0.2.3 vs 1.0.0

| Consideration | Ship as 0.2.3-SNAPSHOT -> 0.2.3 | Ship Directly as 1.0.0 |
|---|---|---|
| **SemVer Guarantee** | Flexible: minor version under `0.x` permits ongoing refinement of internal packages. | Rigid: any future change to the 259 accidental public types would require a 2.0.0 major version bump. |
| **Documentation & Adoption** | Developers immediately receive the full migration guide, error catalog, quickstarts, and Quarkus extension. | Delayed until full modular encapsulation is finished. |
| **Risk Profile** | **Low**: preserves existing binary compatibility while delivering comprehensive documentation and Quarkus support. | **High**: exposes immature surface as permanent contractual obligation. |
| **Recommendation** | **APPROVED**: Release 0.2.3 now. | **REJECTED**: Block until 0.3.0 encapsulation completes. |

## 6. Conclusion

Viet Template has successfully achieved functional, architectural, performance, and documentation maturity. The engine is ready for widespread real-world adoption on the **0.2.x** stream. Proceeding with a **0.2.3 stabilization release** allows external users to migrate from Apache Velocity immediately, while shielding the project from premature 1.0 API freeze commitments.
