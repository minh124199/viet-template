# Viet Template 1.0 Readiness Gap Analysis & Surface Audit

This document provides an exhaustive gap analysis evaluating Viet Template against the **Definition of Done for 1.0.0 General Availability (GA)**. It audits all fifteen architectural areas, details the 99 stable public types versus 257 accidental public types, outlines the encapsulation remediation roadmap, and provides an authoritative release recommendation.

---

## 1. Executive Summary & 1.0 Readiness Verdict

> [!IMPORTANT]
> **Verdict: NOT YET READY FOR IMMEDIATE 1.0.0 GA.**
>
> While Viet Template has achieved 100% VTL language compatibility (80/80 TCK features), decisive performance wins over Apache Velocity 2.4.1 (1.3x–5.3x throughput), enterprise-grade security sandboxing, and full GraalVM/Spring Boot 4 native support, **one critical architectural blocker remains for 1.0.0 GA**:
>
> **The Public Surface Exposure (257 `PUBLIC_BUT_INTERNAL_ACCIDENT` types)**: Under Semantic Versioning 2.0.0, releasing 1.0.0 commits the project to permanent binary and source backwards compatibility for all exported public types. Releasing 1.0.0 with 257 exposed internal implementation types would permanently compromise the project's ability to refactor internals without breaking SemVer.

### Recommended Release Sequence
1. **0.2.3 (Immediate Stabilization & Adoption Release)**:
   - Ship the complete documentation suite, Apache Velocity migration guide, comprehensive diagnostic error catalog, plain Java examples, and build tooling refinements.
   - Maintain the existing baseline while enabling external Java teams to evaluate and migrate to Viet Template.
2. **0.3.0 (Internal Surface Encapsulation Milestone)**:
   - Encapsulate the 257 accidental public types using Java 9+ `module-info.java` qualified exports and package relocation (`*.internal.*`).
   - Re-baseline the public API surface strictly to the 99 verified `STABLE_API` and `STABLE_SPI` types.
3. **1.0.0 GA (General Availability)**:
   - Lock permanent binary backwards compatibility, certified by real-world production adopter validation.

## 3. Surface Audit: 99 Stable Types vs 257 Accidental Public Types

A comprehensive audit of `config/api-baseline/public-surface-classification.txt` reveals the composition of exported Java types across all modules:

### 3.1 Stable Public Types (99 Types)
The 99 stable types represent the intended permanent API/SPI contract of Viet Template:
- **`STABLE_API` (92 Types)**:
  - Core engine entry points: `VietTemplateEngine`, `VietTemplateEngineBuilder`, `TemplateId`, `TemplateSource`.
  - Context & Model API: `RenderContext`, `EvaluationValue`, `TemplateOutput`, `StringTemplateOutput`.
  - Spring Integration: `VietTemplateView`, `VietTemplateViewResolver`, `VietTemplateProperties`.
  - Security API: `MemberAccessPolicy`, `RenderBudget`, `TemplateSecurityException`.
- **`STABLE_SPI` (7 Types)**:
  - `TemplateLoader` (Custom template resolution).
  - `TemplateEscaper` (Custom escaping algorithms).
  - `MemberResolver` (Custom bean/field resolution).
  - `TemplateOutput` (Low-level output streaming).
  - `MethodInvoker` (Custom reflection/dispatch).
  - `ResourceResolver` (Custom include/parse resolution).
  - `VietTemplateEngineCustomizer` (Spring Boot engine customization hook).

### 3.2 Accidental Public Types (257 Types)
The 257 types classified as `PUBLIC_BUT_INTERNAL_ACCIDENT` fall into three major architectural categories:
1. **Parser & AST Nodes (~140 Types)**:
   - Types such as `io.github.minh124199.viettemplate.language.vtl.ast.VtlNode`, `VtlIfDirectiveNode`, `VtlForeachDirectiveNode`, and internal token representations.
   - *Why Public*: The parser and AST reside in `viet-template-language-vtl`, but the interpreter (`viet-template-vtl-interpreter`) and compiler inspect AST node trees. Before JPMS module encapsulation, Java visibility rules required public access across JAR boundaries.
2. **Bytecode Compiler Internals (~60 Types)**:
   - Types such as `BytecodeTemplateCompiler`, `BytecodeNaming`, `DynamicSiteSpec`, `CompilerContext`, and ASM visitor helpers.
   - *Why Public*: The compiler is invoked by build plugins (`viet-template-maven-plugin` and `viet-template-gradle-plugin`), necessitating cross-module accessibility.
3. **Runtime Call-Site & Dispatch Internals (~57 Types)**:
   - Types such as polymorphic inline cache links (`MonomorphicLink`, `PolymorphicLink`), internal frame slots, and buffer pools.
   - *Why Public*: Needed by compiled bytecode classes generated at runtime or build time.

## 4. Remediation Strategy for 1.0 GA (Milestone 0.3.0)

To resolve the 1.0 surface blocker without breaking plugin compilation or runtime bytecode dispatch, Viet Template will execute a three-part encapsulation plan in milestone **0.3.0**:

### Step 1: Java Platform Module System (`module-info.java`)
Introduce `module-info.java` descriptors in all production modules. Use **qualified exports** (`exports ... to ...`) so that internal packages are visible to Viet Template build plugins and compiler modules, but remain strictly inaccessible to consumer applications:
```java
// Example module-info descriptor with qualified exports
module io.github.minh124199.viettemplate.api {
    exports io.github.minh124199.viettemplate.api;
}
```

### Step 2: Package Relocation to `*.internal.*`
Relocate non-SPI implementation classes to subpackages containing `.internal.` (e.g., `io.github.minh124199.viettemplate.core.internal.*`).
- Javadoc generation tools will exclude `*.internal.*` packages from published public documentation.
- The `verify-public-surface-classification.py` check will verify that no types outside `*.internal.*` carry accidental exposure.

### Step 3: Package-Private Visibility Consolidation
Refactor intra-module helper classes to package-private (`default`) visibility where classes share package declarations.

## 5. Decision Matrix: Release 0.2.3 vs 1.0.0

| Consideration | Ship as 0.2.3-SNAPSHOT -> 0.2.3 | Ship Directly as 1.0.0 |
|---|---|---|
| **SemVer Guarantee** | Flexible: minor version under `0.x` permits ongoing refinement of internal packages. | Rigid: any future change to the 257 accidental public types would require a 2.0.0 major version bump. |
| **Documentation & Adoption** | Developers immediately receive the full migration guide, error catalog, and quickstarts. | Delayed until full modular encapsulation is finished. |
| **Risk Profile** | **Low**: preserves existing binary compatibility while delivering comprehensive documentation. | **High**: exposes immature surface as permanent contractual obligation. |
| **Recommendation** | **APPROVED**: Release 0.2.3 now. | **REJECTED**: Block until 0.3.0 encapsulation completes. |

---

## 6. Conclusion

Viet Template has successfully achieved functional, architectural, performance, and documentation maturity. The engine is ready for widespread real-world adoption on the **0.2.x** stream. Proceeding with a **0.2.3 stabilization release** allows external users to migrate from Apache Velocity immediately, while shielding the project from premature 1.0 API freeze commitments.
