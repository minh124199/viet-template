# Ahead-Of-Time (AOT) TypeScript Contract Generation

Viet Template 1.5 introduces first-class, Ahead-Of-Time (AOT) TypeScript contract generation for template inputs.

By projecting `#param` directives, companion contracts, compiled Java models, and canonical schemas directly into deterministic TypeScript declaration files (`*.vtl.d.ts`), your frontend application (e.g. Svelte, React, Vue, or vanilla TypeScript) can import and type-check template parameters with compile-time safety and IDE autocompletion.

---

## Key Principles & Guarantees

1. **Pure Java Execution (Zero Node/npm required)**:
   The TypeScript contract generator (`TypeScriptContractProjector`) is written in 100% pure Java. Standard Maven and Gradle builds generate `.vtl.d.ts` files without requiring Node.js, npm, or any JavaScript toolchain.
2. **Byte-for-Byte & SHA-256 Maven/Gradle Parity**:
   The output produced by Maven (`generate-typescript-contracts`) and Gradle (`generateTypeScriptContracts`) is strictly byte-for-byte identical for identical template inputs.
3. **Safe Stale File Cleanup via Manifest**:
   The generator maintains a tracking manifest (`.viet-template-typescript-manifest.json`) in the output directory. When a template is renamed or deleted, only previously generated files owned by the manifest are cleaned up. Foreign or hand-crafted files in the directory are never deleted.
4. **Incremental `writeIfChanged` Avoidance**:
   Files are rewritten only when their generated content has actually changed. If the output is identical, the file's modification timestamp (`mtime`) is preserved, preventing unwanted rebuild loops in downstream frontend watchers (e.g., Vite, webpack, tsc).
5. **Security & Sandbox Isolation**:
   The projector strictly enforces `MemberAccessPolicy`. Restricted methods such as `getClass()`, `ClassLoader`, `Thread`, and reflection internals are excluded from generated contracts.

## How It Works

Given a template `src/main/viet-template/orders/detail.vtl`:

```velocity
#param(String $customer)
#param(long $orderId)
#param(double $total)
#param(List<String>? $notes)

<div class="order">
    <h2>Order #$orderId</h2>
    <p>Customer: $customer</p>
    <p>Total: $total</p>
</div>
```

The generator produces `build/generated/viet-template/typescript/orders/detail.vtl.d.ts`:

```typescript
// Generated by Viet Template M46. Do not edit directly.
// Source: orders/detail.vtl

export interface OrdersDetailTemplateParameters {
  customer: string;
  orderId: number;
  total: number;
  notes?: string[] | null;
}

export interface OrdersDetailTemplateContract {
  parameters: OrdersDetailTemplateParameters;
}

export default OrdersDetailTemplateContract;
```

Frontend components can then import this contract:

```typescript
import type { OrdersDetailTemplateParameters } from './orders/detail.vtl';

export function renderOrder(data: OrdersDetailTemplateParameters) {
  console.log(`Processing order #${data.orderId} for ${data.customer}`);
}
```

## Maven Configuration

Bind the `generate-typescript-contracts` goal to your build lifecycle (defaults to `process-classes`):

```xml
<plugin>
    <groupId>io.github.minh124199</groupId>
    <artifactId>viet-template-maven-plugin</artifactId>
    <version>1.5.0-SNAPSHOT</version>
    <executions>
        <execution>
            <id>generate-typescript-contracts</id>
            <goals>
                <goal>generate-typescript-contracts</goal>
            </goals>
            <configuration>
                <sourceDirectory>${project.basedir}/src/main/viet-template</sourceDirectory>
                <typeScriptOutputDirectory>${project.build.directory}/generated-sources/viet-template/typescript</typeScriptOutputDirectory>
                <cleanStaleOutputs>true</cleanStaleOutputs>
            </configuration>
        </execution>
    </executions>
</plugin>
```

### Maven Plugin Configuration Options

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `sourceDirectory` | `File` | `${project.basedir}/src/main/viet-template` | Root directory containing template sources. |
| `typeScriptOutputDirectory` | `File` | `${project.build.directory}/generated-sources/viet-template/typescript` | Output directory for generated `.vtl.d.ts` and manifest files. |
| `schemaDirectory` | `File` | `${project.build.directory}/generated-resources/viet-template/schemas` | Optional directory containing pre-generated canonical schemas (`*.vt-schema.json`). |
| `includes` | `List<String>` | `**/*.vtl`, `**/*.vm`, `**/*.vtl.html` | Ant-style patterns of templates to include. |
| `excludes` | `List<String>` | *(empty)* | Ant-style patterns of templates to exclude. |
| `encoding` | `String` | `UTF-8` | Character encoding of input templates. |
| `cleanStaleOutputs` | `boolean` | `true` | When true, cleans up stale outputs owned by the generator manifest. |
| `skip` | `boolean` | `false` | Skips execution of the goal. |

## Gradle Configuration

Apply the `io.github.minh124199.viet-template` plugin in your `build.gradle.kts`:

```kotlin
plugins {
    java
    id("io.github.minh124199.viet-template") version "1.5.0-SNAPSHOT"
}

vietTemplate {
    sourceDirectory.set(file("src/main/viet-template"))
    typeScriptOutputDirectory.set(layout.buildDirectory.dir("generated/viet-template/typescript"))
}
```

The task `generateTypeScriptContracts` is automatically registered and wired into the `classes` lifecycle task.

### Customizing the Gradle Task Directly

```kotlin
tasks.named<io.github.minh124199.viettemplate.tooling.gradle.VietTemplateGenerateTypeScriptContractsTask>("generateTypeScriptContracts") {
    cleanStaleOutputs.set(true)
    encoding.set("UTF-8")
    includes.set(listOf("**/*.vtl", "**/*.vtl.html"))
}
```

### Gradle Task Properties

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `sourceDirectory` | `DirectoryProperty` | `src/main/viet-template` | Input directory containing template files. |
| `typeScriptOutputDirectory` | `DirectoryProperty` | `build/generated/viet-template/typescript` | Destination directory for `.vtl.d.ts` declarations. |
| `schemaDirectory` | `DirectoryProperty` | `build/generated/viet-template/schemas` | Optional input directory for pre-generated schemas. |
| `includes` | `ListProperty<String>` | `["**/*.vtl", "**/*.vm", "**/*.vtl.html"]` | Inclusion patterns for template files. |
| `excludes` | `ListProperty<String>` | `[]` | Exclusion patterns for template files. |
| `encoding` | `Property<String>` | `"UTF-8"` | File encoding for templates. |
| `cleanStaleOutputs` | `Property<Boolean>` | `true` | Enables safe stale cleanup via the manifest file. |
| `classpath` | `ConfigurableFileCollection` | `compileClasspath + classes` | Compile classpath used to resolve Java models and companion contracts. |

## Type Projections Reference

| Java / VTL Type | Generated TypeScript Type |
| :--- | :--- |
| `String`, `CharSequence`, `char`, `Character`, `UUID` | `string` |
| `int`, `Integer`, `long`, `Long`, `short`, `byte`, `float`, `double`, `BigDecimal`, `BigInteger` | `number` |
| `boolean`, `Boolean` | `boolean` |
| `Instant`, `LocalDate`, `LocalDateTime`, `OffsetDateTime`, `ZonedDateTime`, `Date` | `string` (ISO-8601 string) |
| `T[]`, `List<T>`, `Set<T>`, `Collection<T>`, `Iterable<T>` | `T[]` |
| `Map<String, V>` | `Record<string, V>` |
| Java Record / POJO | Typed interface with projected properties |
| Nested class (`Outer.Inner`) | Normalized interface name `Outer_Inner` |
| Nullable / Optional (`Type?`, `Optional<T>`) | `T \| null` |
| Generic class | Reified parameter types |
