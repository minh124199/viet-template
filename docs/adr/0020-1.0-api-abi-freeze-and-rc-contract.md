# ADR-0020: 1.0 Release Candidate API Freeze, ABI Lock, and Tooling Contract

## Status
**ACCEPTED / FROZEN** (Milestone M8)

## Date
2026-09-24

## Context

Following the completion and qualification of milestones M1 through M7.9.8, Viet Template has achieved complete internal surface encapsulation, backend parity, warmed-lookup simplification, fail-closed runtime exception semantics, and framework integration parity across Spring Boot 3/4 and Quarkus JVM/native.

Milestone M8 formally transitions the project from architecture engineering into release engineering. To prepare candidate release artifacts (such as `1.0.0-RC1`) and validate external consumption without risk of contract drift, the repository requires an authoritative, multi-dimensional freeze covering public APIs, SPIs, generated template runtime ABI, diagnostic codes, framework configuration properties, and build-tool contracts.

## Decision

The project formally executes the 1.0 Candidate Contract Freeze across the following dimensions:

### 1. Freeze Status Taxonomy

The repository governance distinguishes six precise categories:
1. `FROZEN_1_0_API` (94 types): Public consumer contracts locked under SemVer 2.0.0 backwards compatibility guarantees for 1.x.
2. `FROZEN_1_0_SPI` (27 types): Extension interfaces for third-party implementors (e.g. `TemplateRepository`, `TemplateFreshnessProvider`, `FreshnessToken`, `MemberAccessPolicy`, `TemplateOutput`, `VietTemplateEngineCustomizer`, `SecurityViewFactory`).
3. `FROZEN_1_0_GENERATED_ABI` (7 types, 22 methods, 0 fields): Bytecode linkage dependencies invoked by precompiled template classfiles.
4. `FROZEN_1_0_DIAGNOSTIC_CODE` (31 canonical codes): Machine-readable diagnostic identifiers emitted by compiler, parser, runtime, and framework components.
5. `EXPERIMENTAL` (5 types): Emerging compiler/runtime capabilities subject to evolution prior to 1.0 GA and exempt from 1.x compatibility guarantees.
6. `INTERNAL` (136 types): Implementation classes, including 85 `PUBLIC_BUT_INTERNAL_ACCIDENT` (PBCIA) debt types tracked in `config/architecture/public-surface-debt-registry.json` as non-blocking P2 debt deferred to post-1.0 (M22 module boundary review).

### 2. Definition of API Freeze

**Frozen for 1.x**:
- Fully qualified class names (FQCNs) of all `STABLE_API` and `STABLE_SPI` types.
- Public and protected method and field signatures on stable types.
- Exception throwing contracts on public entry points.
- Stable diagnostic-code string identifiers.
- Framework configuration property names (`viet-template.*`, `quarkus.viet-template.*`).
- Maven plugin goal `compile`, phase `process-classes`, and Mojo parameter names/defaults.
- Gradle plugin ID `io.github.minh124199.viet-template`, task `compileVietTemplates`, extension `vietTemplate`, and task wiring.
- Artifact coordinates across the 12 published production modules and the root parent POM.

**NOT Frozen (Subject to Internal Evolution)**:
- Non-public implementation classes, private helpers, and internal algorithms.
- Unexported bytecode structures and internal IR representations.
- `EXPERIMENTAL` APIs.
- Unpublished benchmark internals and test harnesses.
- Human-readable English phrasing of diagnostic messages (codes remain invariant).
- Internal caching algorithms and non-contractual performance characteristics.

### 3. Generated Runtime ABI Candidate Freeze

Generated template classfiles depend on exactly 7 Viet-owned types, 22 invoked methods, and 0 fields:

1. `io.github.minh124199.viettemplate.api.CompiledTemplate` (`STABLE_API`)
2. `io.github.minh124199.viettemplate.api.RenderContext` (`STABLE_API`): `get(String)`
3. `io.github.minh124199.viettemplate.api.TemplateId` (`STABLE_API`): `of(String)`
4. `io.github.minh124199.viettemplate.api.TemplateOutput` (`STABLE_SPI`): opaque sink parameter
5. `io.github.minh124199.viettemplate.language.vtl.semantics.scope.ForeachMetadata` (`PUBLIC_BUT_INTERNAL_ACCIDENT`):
   - Exactly 4 methods are designated `GENERATED_ABI_FROZEN`: `int getCount()`, `int getIndex()`, `boolean isFirst()`, `boolean isLast()`.
   - The type itself remains unpromoted as general application API.
6. `io.github.minh124199.viettemplate.runtime.linker.DynamicCallSite` (`INTERNAL_CROSS_PACKAGE`):
   - Treated strictly as an opaque token passed into `BytecodeRuntimeBridge` dispatcher methods (`dynamicGetProperty`, `dynamicGetIndex`, `dynamicInvokeMethod`).
   - No methods, fields, or internal state of `DynamicCallSite` are frozen or callable by generated bytecode.
7. `io.github.minh124199.viettemplate.vtl.compiler.bytecode.BytecodeRuntimeBridge` (`GENERATED_RUNTIME_ABI`):
   - 16 static runtime bridge methods (`binaryOp`, `unaryOp`, `isTruthy`, `rangeIterator`, `toIterator`, `toUtf8Bytes`, `countLoopIteration`, `createCallSite`, `createForeachMetadata`, `createLoopState`, `dynamicGetIndex`, `dynamicGetProperty`, `dynamicInvokeMethod`, `recordContextVariable`, `writeConst`, `writeValue`).

**Generated ABI Freeze Invariant**: No type descriptor, method descriptor, or constructor shape in this 7-type / 22-method set may be modified during the 1.0 candidate line except for an explicitly declared and documented `FREEZE_EXCEPTION`.

### 7. Publication Topology

- 12 production modules + parent POM = 13 published artifacts under groupId `io.github.minh124199`.
- 2 unpublished verification modules: `viet-template-tck`, `viet-template-benchmarks`.
- Factual omission of `Automatic-Module-Name` (`NO_AUTOMATIC_MODULE_NAME_HEADER`).
- Quarkus modules (`viet-template-quarkus`, `viet-template-quarkus-deployment`) were introduced on the 0.3.0 development line and have never been published (`Never published. First intended release: 0.3.0+ / 1.0 candidate line`).

### 8. Change-Control Policy After Freeze

Any modification to frozen surfaces after the freeze commit requires:
1. Classification as `RC_BLOCKER_FIX`, `RELEASE_METADATA_FIX`, `PACKAGING_FIX`, `DOCUMENTATION_FIX`, or `TEST_INFRASTRUCTURE_FIX`.
2. Explicit `FREEZE_EXCEPTION` record documenting the issue, impact, and justification.
3. Full re-execution of the qualification suite.

## Consequences

- Stable contracts are frozen and protected against unintentional modification.
- Release candidate packaging and external consumer qualification can proceed with verifiable baselines.
- Internal technical debt (85 PBCIA types) remains isolated behind non-blocking P2 status and deferred to M22.
