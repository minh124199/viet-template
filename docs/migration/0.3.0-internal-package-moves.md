# Internal Package Moves (Viet Template 0.3.0)

This document provides the migration reference for types relocated during **Milestone M22.2 (0.3.0-M2)**.

## Architectural Context

As part of the path toward 1.0 GA stability, Viet Template separates its API surface into:
1. **`STABLE_API` / `STABLE_SPI`** (105 types): Covered by semantic versioning compatibility guarantees.
2. **`EXPERIMENTAL`** (6 types): Evolving APIs clearly marked as preview.
3. **`PUBLIC_BUT_INTERNAL_ACCIDENT`**: Classes historically marked `public` solely to allow cross-package access within the engine before full modularization.

In **Milestone M22.1 (0.3.0-M1)**, 34 internal types with strictly package-scoped usage were demoted to `package-private`.
In **Milestone M22.2 (0.3.0-M2)**, 49 internal implementation types with same-module cross-package dependencies were moved into dedicated `*.internal.*` packages.

> [!NOTE]
> Public applications and framework integrations targeting standard APIs (`io.github.minh124199.viettemplate.api.*`, `TemplateEngine`, `VietTemplateRenderer`, Spring Boot starters, Quarkus extension) are **completely unaffected**. No stable API signatures were changed or broken.

## Reclassified Types (Retained in Category C)

During validation, 17 types originally listed as Category-B candidates were reclassified to **Category C (Cross-Module Internal SPI Required)** to satisfy language and compatibility boundaries:

1. **JLS 8.1.6 Sealed Hierarchy Permit Boundaries**:
   - `IrBranch`, `IrBranchIf`, `IrLoopEnd`, `IrLoopNext`, `IrLoopSetup` (5 types)
   - *Reason*: Direct permitted implementations of sealed interface `IrStatement` in an unnamed module must remain co-located in the same package as `IrStatement` (`io.github.minh124199.viettemplate.language.vtl.ir.statement`).
2. **Stable API Signature Leak Protection**:
   - `SpaceGobbler`, `TemplateResource`, `TemplateResourceResolver` (+ `$InMemoryBuilder`), `VtlSecurityPolicy` (5 types)
   - *Reason*: Directly referenced in the public method signatures of `VtlInterpreterOptions` (a frozen `STABLE_API` in `1.0-core-public-api.txt`). Relocation would break binary/source compatibility of the stable API.
3. **Framework Reflection Metadata**:
   - `VietTemplateRuntimeHints` (1 type)
   - *Reason*: Explicitly referenced by FQCN in `META-INF/spring/aot.factories` for Spring AOT hints.
4. **Cross-Module Benchmarks & Stress Tests**:
   - `EvaluationValue`, `ExecutionFrame` (2 types)
   - *Reason*: Directly invoked by `viet-template-benchmarks` production evaluation code.
5. **Optimizer Pass Package Boundaries**:
   - `AssignVariableSlots`, `OptimizationContext` (2 types)
   - *Reason*: Depend on package-private optimizer passes `IrOptimizationPass` and `OptimizationStatistics`.
6. **Cross-Package Engine/Interpreter Bridge**:
   - `LinkedReferenceAccess`, `ReferenceAccess` (2 types)
   - *Reason*: Inter-package bridge between `vtl.engine` and `vtl.interpreter` requiring package-private access to `DefaultReferenceAccess`, `VtlLinkerAccessPolicyAdapter`, and `ControlSignal`.

These types are systematically addressed across **Milestone 0.3.0-M3** subphases under formal internal SPI contracts and visibility containment.

## Classification Update — 0.3.0-M3.5

### New Category: `INTERNAL_CROSS_PACKAGE`

The public surface taxonomy now includes `INTERNAL_CROSS_PACKAGE` as a distinct category separate
from `PUBLIC_BUT_INTERNAL_ACCIDENT`. Types classified as `INTERNAL_CROSS_PACKAGE` are
**intentionally public** within their owning artifact due to cross-package callers in the same JAR.
They are not accidental — the package structure is deliberate — but external usage is unsupported
and no binary or source compatibility guarantee applies pre-1.0.

**Affected subsystems (55 types total):**
- `vtl.internal.compiler.*` — bytecode compiler pipeline types (BackendId, BackendOptions, BytecodeNaming, ClassFileWriter, etc.)
- `vtl.internal.engine.*` — engine internals (ContributingContextComposer, StaticDependencyExtractor, GlobalMacroManager, DevelopmentFileWatcher, etc.)
- `vtl.internal.interpreter.*` — interpreter utilities (CountingTemplateOutput, InterpreterDiagnosticCodes, VtlComparisonOperations, VtlNumericOperations)
- `vtl.engine.cache.*` — compile cache types (CompileCacheKey, CompiledTemplateHandle, TemplateCompileCache)
- `vtl.engine.dependency.*` — dependency graph impl (DefaultTemplateDependencyGraph)
- `language.vtl.internal.*` — internal AST, IR plan, and semantics utilities (ReferenceNotation, BudgetKind, DynamicAccessSite, TemplateCapabilities, MemberResolution, SymbolTable, etc.)
- `runtime.linker.*` — linker internals (BoundedWeakClassCache, DynamicCallSite)

### New Category: `BENCHMARK_SUPPORT_INTERNAL`

Three types previously classified as `INTERNAL_CROSS_MODULE` have been reclassified to
`BENCHMARK_SUPPORT_INTERNAL`: `EvaluationValue$State`, `ExecutionFrame`, and
`ForeachMetadata` (vtl.interpreter). These are consumed **only** by the unpublished JMH benchmark
suite (`viet-template-benchmarks`, `maven.deploy.skip=true`). Production modules do not use them.

### Debt Registry

All remaining 85 `PUBLIC_BUT_INTERNAL_ACCIDENT` types are now tracked in
`config/architecture/public-surface-debt-registry.json` with target milestones and remediation plans.
