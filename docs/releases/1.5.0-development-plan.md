## 1. Executive Summary & 1.5.0 Thesis

Following the successful GA release and Maven Central publication of Viet Template 1.4.0 (introducing Frontend Asset Integration and the Safe Client Data Bridge), this document establishes the strategic direction, candidate qualification, and milestone sequence for the **Viet Template 1.5 minor feature line**.

### 1.1 The 1.5.0 Strategic Thesis

> **Viet Template 1.5 focuses on optional compile-time type intelligence, type-safe template parameter contracts, and schema-to-client TypeScript projection—delivering robust compile-time validation and rich IDE typing without compromising 100% dynamic VTL runtime compatibility or introducing external runtime dependencies.**

### 1.2 Core Value Proposition
1. **Type Safety Without Rigidity**: Developers can optionally declare expected template parameters (via `#param` directives or companion schema declarations). When present, the template compiler and Language Server validate variable accesses, methods, and record components ahead-of-time. When absent, templates retain full dynamic VTL dispatch.
2. **End-to-End Contract Projection**: Extends the 1.4 Safe Client Data Bridge (`$clientData`) by projecting companion schemas and Java view models directly into TypeScript type definitions (`.d.ts`), enabling typed frontend component islands (Svelte 4/5, React, Vue) without manual type duplication.
3. **Framework-Level View Model Validation**: Integrates view-model validation into Spring Boot and Quarkus test fixtures and AOT compilation steps, catching controller-to-template attribute mismatches during build time.
4. **Zero-Runtime-Dependency Invariant**: Core runtime remains 100% JDK-only. Node and npm remain strictly quarantined to build-time frontend bundle generation; the server-side runtime requires zero JavaScript engines or Node processes.

### 2.1 Candidate Disposition Legend
- `SELECT_FOR_1_5`: Qualified for implementation in the 1.5.0 milestone arc.
- `QUALIFY_FIRST`: Architectural feasibility prototype required before commitment.
- `DEFER`: Valid capability, but deferred to a future line (e.g. 1.6+ or post-1.5).
- `PATCH_LINE`: Bug fix, security update, or doc correction belonging to `release/1.4` (`1.4.x`).
- `REQUIRES_MAJOR`: Breaking change forbidden in minor line; deferred to 2.0.0+.
- `REJECT`: Incompatible with project architectural invariants (e.g. zero-Node Java runtime).
- `ALREADY_COMPLETE`: Verified as already implemented in 1.0–1.4.

## 3. Architectural Leverage & Invariant Protections

### 3.1 Architectural Leverage
The 1.5 feature line maximizes leverage of existing verified subsystems:
- **Existing IR & AST Infrastructure**: Optional parameter declarations map into existing AST nodes and `IrTemplate` structures without introducing a second parser.
- **Existing Tooling Schema (`.vt-schema`)**: Reuses the canonical tooling schema established in M27 and extended in M41.
- **Existing Language Server Protocol (LSP)**: Leverages the LSP engine established in M29/M38–M41 to deliver type-assisted completions and diagnostics.
- **Existing Safe Client Data Bridge**: Reuses `ClientData` and `SimpleJsonSerializer` from M43, projecting schema types directly into frontend TypeScript definitions.

### 3.2 Non-Negotiable Project Invariants
1. **Dynamic VTL Backwards Compatibility**: Templates without `#param` declarations MUST execute with 100% dynamic Velocity compatibility.
2. **Zero Runtime Node/npm Footprint**: Normal Java applications executing Viet Template MUST NOT require Node, npm, or an embedded JavaScript runtime.
3. **Mandatory Native Image Compatibility**: All additions must preserve GraalVM and Mandrel native compilation without reflection configuration regressions.
4. **Java 21 Compiler Baseline**: Strict `--release 21` compilation target. Java 25 remains primary performance qualification environment.
5. **Fail-Closed Security**: Type information must never weaken security sandboxing or bypass `MemberAccessPolicy`.

## 5. Explicit Non-Goals for 1.5.0

To maintain velocity, stability, and adherence to core values, the following are explicitly declared non-goals for 1.5:
1. **No Breaking Syntax Changes**: Existing VTL templates MUST parse and render identically without modification.
2. **No Mandatory Static Typing**: Static typing MUST remain strictly opt-in.
3. **No Node/npm Runtime Coupling**: Java applications executing Viet Template MUST NOT depend on Node.js at runtime.
4. **No Server-Side JavaScript Execution**: No embedded V8, GraalJS, or QuickJS runtime engines on the server.
5. **No Java Baseline Elevation**: Minimum compiler baseline remains Java 21 LTS (`--release 21`).
6. **No JPMS Modularization**: Java Platform Module System (`module-info.java`) migration is deferred to 2.0.0+.
7. **No Arbitrary Performance Micro-Optimizations**: Performance changes must be justified by fresh multi-JDK JMH evidence showing $\ge 5\%$ steady-state hotspot impact.
