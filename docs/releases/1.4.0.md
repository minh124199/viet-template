## 1. Highlights

Viet Template 1.4.0 introduces **Frontend Asset Integration** and the **Safe Client Data Bridge**, seamlessly connecting compile-first JVM SSR with modern frontend tooling (Vite 5 / Vite 8) and reactive component islands (Svelte 4 / Svelte 5).

Key advancements include:
- **Zero-Node Runtime Asset Pipeline**: Resolves Vite production build manifests (`.vite/manifest.json` and legacy `manifest.json`) and development server assets without requiring Node, npm, or external processes in the Java build lifecycle or request hot path.
- **Contextual View Helpers**: Context-aware `$assets.head(...)` and `$assets.body(...)` render helpers automatically emit scripts, stylesheets, and module preloads with deduplication and integrity.
- **Script-Safe Client Data Bridge**: Streaming unicode-escaped JSON serializer (`ClientData.script(...)`) converts `<`, `>`, `&`, and ECMAScript line terminators (`\u2028`, `\u2029`) into escape sequences, preventing script breakout attacks in `<script type="application/json">` islands.
- **Framework Parity**: Native auto-configuration for Spring Boot 4 / Spring MVC and build-time CDI integration for Quarkus 3.39.4, complete with GraalVM / Mandrel native-image resource registration.
- **Strict Backward Compatibility**: Exactly **0 breaking changes** against all frozen 1.0.0 public baselines across core, AOT, Spring, Spring Security, and Quarkus.
- **Real-Browser Parity Qualification**: Production SSR, authenticated CSRF handling, and Vite HMR verified in headless Chromium across Spring Boot and Quarkus.

## 2. Frontend Asset Integration

Viet Template 1.4.0 delivers first-class, opt-in frontend asset integration designed for modern bundlers:
- **Core Abstractions (`viet-template-runtime`)**:
  - `AssetResolver`: SPI for resolving frontend entries and individual asset references.
  - `ResolvedFrontendEntry`: Models an entry point with associated scripts, stylesheets, and module preloads.
  - `FrontendAssets`: Template helper exposed as `$assets`, providing `$assets.head(entry)` and `$assets.body(entry)` with cross-entry deduplication.
  - `FrontendAssetsRenderContextContributor`: Automatically contributes `$assets` and `$clientData` helpers into rendering contexts.
- **Vite Asset Resolver (`io.github.minh124199.viettemplate.assets.vite`)**:
  - `ViteAssetResolver`: Built-in zero-dependency resolver supporting both production manifest mode and development dev-server mode (`ViteAssetMode.DEVELOPMENT` / `ViteAssetMode.PRODUCTION`).
  - Production mode: In-memory cached lookup of entry scripts, imported chunks, extracted CSS, and module preloads.
  - Development mode: Automatic `@vite/client` injection, dynamic HMR script generation, and configurable server URLs.

## 3. Framework Integration

Viet Template 1.4.0 provides complete feature parity across Spring Boot and Quarkus:

### Spring Boot 4
- `VietTemplateAssetAutoConfiguration`: `FRAMEWORK_ENTRYPOINT` registering `AssetResolver`, `FrontendAssets`, `ClientData`, and `FrontendAssetsRenderContextContributor` beans when asset support is enabled.
- Configuration properties via `viet-template.assets.*` (`VietTemplateAssetProperties`, `VietTemplateAssetProperties$Vite`):
  - `viet-template.assets.enabled`: Global toggle (defaults to `true`).
  - `viet-template.assets.mode`: `development` or `production`.
  - `viet-template.assets.vite.server-url`: Dev server URL (default `http://localhost:5173`).
  - `viet-template.assets.vite.manifest-path`: Production manifest path (default `classpath:/META-INF/resources/dist/.vite/manifest.json`).

### Quarkus 3.39.4
- `VietTemplateProducer`: CDI producer methods for `AssetResolver`, `FrontendAssets`, `ClientData`, and `ClientDataSerializer`.
- `VietTemplateProcessor`: Build-time processor registering `NativeImageResourceBuildItem` for Vite manifests and client-data resources during GraalVM/Mandrel native compilation.
- `VietTemplateConfig`: Type-safe configuration via `@ConfigMapping` with `@WithDefault` attributes.

## 4. Security

- **Safe JSON Serialization**: `ClientData` provides streaming unicode-escaped serialization for embedded JSON state islands:
  - Escapes `<`, `>`, `&`, preventing `</script>` tags and HTML context breakouts.
  - Escapes ECMAScript line separators `\u2028` and paragraph separators `\u2029`, preventing JavaScript parsing errors.
- **Built-in Zero-Dependency Serializer**: `ClientData.defaultSerializer()` supports primitives, collections, maps, dates (ISO-8601 UTC), and reflective JavaBean/record inspection with package-private encapsulation.
- **Jackson Serializer Adapter**: `JacksonClientDataSerializer` provides reflection-based compatibility with both Jackson 2.x and Jackson 3.x `ObjectMapper` without hard compile-time binding.
- **Authenticated CSRF Parity**: Production browser qualification validates CSRF tokens across both Spring Security 7 and Quarkus Security + REST CSRF, ensuring identical protection for reactive island mutations.

## 8. Fixed

- **Quarkus SmallRye Config Mapping**: Fixed `VietTemplateConfig.java` where methods with default interface bodies were skipped by SmallRye `@ConfigMapping` bytecode generation and marked as unrecognized properties; converted to abstract methods with `@WithDefault(...)`.
- **Quarkus Arc CDI Self-Lookup Recursion**: Fixed `StackOverflowError` in `VietTemplateProducer.produceClientDataSerializer()` caused by container self-lookup of `ClientDataSerializer` inside its own `@DefaultBean` producer method.

---

## 9. Upgrade Notes

- Upgrading from 1.3.0 to 1.4.0 requires zero changes to existing template files or application code.
- To enable Frontend Asset Integration in Spring Boot, ensure `viet-template-spring-boot-starter` is present and configure `viet-template.assets.*` properties.
- To enable Frontend Asset Integration in Quarkus, add `viet-template-quarkus` and inject `FrontendAssets` or `AssetResolver`.
- Ordinary builds continue to run with standard Maven 3.9+ or Gradle 8.5+ without Node or npm installed.
