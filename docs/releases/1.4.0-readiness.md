## 3. Semantic Version Decision Record

The repository adheres strictly to [Semantic Versioning 2.0.0](https://semver.org/).

### Decision: `MINOR` (`1.3.1-SNAPSHOT` -> `1.4.0-SNAPSHOT`)

#### Empirical Justification
1. **Backwards-Compatible New Functionality**: Post-1.3.0 work introduces a comprehensive new subsystem—**Frontend Asset Integration and Safe Client Data Bridge**—enabling zero-Node SSR asset resolution for Vite 5 and Vite 8 bundles, streaming unicode-escaped JSON client data serialization, and native auto-configuration across Spring Boot 4 and Quarkus 3.39.4.
2. **Stable Public API/SPI Additions**:
   - Exactly **17 new `STABLE_API` types** added to `viet-template-runtime` and `viet-template-spring-boot-autoconfigure`.
   - Exactly **2 new `STABLE_SPI` types** (`AssetResolver`, `ClientDataSerializer`) added for extensible asset and serialization providers.
   - Exactly **1 new `FRAMEWORK_ENTRYPOINT`** (`VietTemplateAssetAutoConfiguration`) registered for Spring Boot auto-configuration.
3. **Zero Breaking Changes**: Binary and source compatibility audits against all 5 frozen 1.0.0 baselines (`core`, `aot`, `spring`, `spring-security`, `quarkus`) prove **0 breaking changes** (0 removed types, 0 removed methods, 0 removed fields, 0 incompatible modifier changes).

#### Rejected Alternatives
- **PATCH (`1.3.1`)**: Rejected because patch releases are reserved for backwards-compatible bug fixes, security corrections, and non-user-visible maintenance. Releasing 19 new stable public API/SPI contracts and an entire end-user asset pipeline in a patch increment violates Semantic Versioning.
- **MAJOR (`2.0.0`)**: Rejected because the release contains zero breaking public contract changes, zero incompatible bytecode modifications, and full backwards compatibility with earlier 1.x releases.

## 7. Known Defects Fixed During Qualification

1. **Quarkus SmallRye ConfigMapping Incompatibility**:
   - *Symptom*: Default interface methods in `VietTemplateConfig` were skipped during SmallRye `@ConfigMapping` bytecode generation, triggering runtime `SRCFG00040: Unrecognized configuration property` errors for asset keys.
   - *Fix*: Converted default interface methods to abstract methods with `@WithDefault(...)` annotations.
   - *Regression Test*: `VietTemplateExtensionTest.java`.
2. **Arc CDI ClientDataSerializer Recursion**:
   - *Symptom*: `StackOverflowError` in `VietTemplateProducer.produceClientDataSerializer()` due to CDI container self-lookup inside its own `@DefaultBean` producer method.
   - *Fix*: Directly instantiated default serializer without recursive container lookup.
   - *Regression Test*: `VietTemplateRendererTest.java`.
