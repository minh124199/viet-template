## 1. Executive Summary & Starting State

Following the completion of Milestone M19.3b.1 (Zero-Allocation Direct Primitive Number Formatting, merged in commit `e4908f9`), the project addressed the second major allocation source identified during M19.3b profiling: **HTML escaping intermediate segment allocation**.

Prior to this milestone:
1. `HtmlTextEscaper.escape(CharSequence, TemplateOutput)` scanned the input string for escapable characters (`&`, `<`, `>`, `"`, `'`).
2. When escapable characters were found, unescaped literal ranges between escape entities were sliced via `input.subSequence(last, i)`.
3. For standard `java.lang.String` inputs, `subSequence()` delegates to `String.substring()`, allocating a new `String` object on the heap for every contiguous unescaped run.
4. In typical HTML documents containing multiple escaped variables or mixed text, these temporary string segments generated heavy GC allocation pressure (from $184\text{ B/op}$ to $880\text{ B/op}$ in microbenchmarks).

Milestone M19.3b.2 eliminates all temporary `subSequence()` and `substring()` allocations by introducing range-streaming directly into `TemplateOutput`.

## 3. Legacy HTML Escaping Architecture & Deficiencies

The legacy escaping loop in [`HtmlTextEscaper.java`](file:///home/lynguyen/current_source/viet-template-repo/viet-template-runtime/src/main/java/io/github/minh124199/viettemplate/runtime/HtmlTextEscaper.java) was:

```java
// Legacy HtmlTextEscaper.java
output.write(input.subSequence(0, firstSpecial));
output.write(replacement);
int last = firstSpecial + 1;
for (int i = firstSpecial + 1; i < len; i++) {
  char c = input.charAt(i);
  String rep = replacementFor(c);
  if (rep != null) {
    if (i > last) {
      output.write(input.subSequence(last, i)); // <-- ALLOCATION
    }
    output.write(rep);
    last = i + 1;
  }
}
if (last < len) {
  output.write(input.subSequence(last, len));   // <-- ALLOCATION
}
```

### Inherent Deficiencies:
1. **Pervasive Substring Heap Allocation**: In an input like `Hello <user> & goodbye!`, `subSequence(0, 6)` ("Hello "), `subSequence(7, 11)` ("user"), `subSequence(12, 14)` (" "), and `subSequence(15, 25)` (" goodbye!") each materialized a new `java.lang.String` instance on the heap.
2. **Double Traversal & Copying**: Each `substring` called `Arrays.copyOfRange`, copying UTF-16 characters or Latin-1 bytes into a new object, only for `output.write(CharSequence)` to iterate or re-encode those bytes immediately afterward.
3. **High GC Headroom Exhaustion**: In high-throughput web rendering workloads, these short-lived strings flooded the JVM young generation, driving up minor GC pause times.

---

## 4. New Zero-Allocation Range-Streaming Architecture

The new architecture streams character ranges directly from the original source `CharSequence` into the destination `TemplateOutput` using index boundaries `[start, end)`:

$$\text{CharSequence } S \xrightarrow{\text{scan } [start, end)} \text{TemplateOutput.write}(S, start, end) \xrightarrow{\text{direct buffer append}} \text{Target Buffer}$$

No intermediate `CharSequence`, `String`, or `char[]` is created during range streaming.

## 5. Implementation Details: `TemplateOutput` Contract

In [`viet-template-api`](file:///home/lynguyen/current_source/viet-template-repo/viet-template-api/src/main/java/io/github/minh124199/viettemplate/api/TemplateOutput.java), a new default method was added to the public SPI:

```java
default void write(CharSequence value, int start, int end) throws IOException {
  if (value == null) {
    return;
  }
  Objects.checkFromToIndex(start, end, value.length());
  for (int i = start; i < end; i++) {
    write(value.charAt(i));
  }
}
```

### Contract Guarantees:
- **Null Safety**: Passing `null` is a safe no-op.
- **Index Bounds**: Index verification via `Objects.checkFromToIndex(start, end, value.length())` ensures strict index safety.
- **Backward Binary Compatibility**: Existing external custom `TemplateOutput` implementations continue to function via the character fallback loop without recompilation or source breakage.

## 7. Implementation Details: `Utf8OutputStreamTemplateOutput` Direct UTF-8 Range Encoding

[`Utf8OutputStreamTemplateOutput.java`](file:///home/lynguyen/current_source/viet-template-repo/viet-template-runtime/src/main/java/io/github/minh124199/viettemplate/runtime/Utf8OutputStreamTemplateOutput.java) overrides `write(CharSequence, int, int)` with zero-allocation UTF-8 byte encoding directly into the internal 8KB buffer:

```java
@Override
public void write(CharSequence value, int start, int end) throws IOException {
  if (value == null) {
    return;
  }
  Objects.checkFromToIndex(start, end, value.length());
  for (int i = start; i < end; i++) {
    char c = value.charAt(i);
    if (c < 0x80) {
      if (count >= buffer.length) {
        flushBuffer();
      }
      buffer[count++] = (byte) c;
    } else if (c < 0x800) {
      if (count + 2 > buffer.length) {
        flushBuffer();
      }
      buffer[count++] = (byte) (0xc0 | (c >> 6));
      buffer[count++] = (byte) (0x80 | (c & 0x3f));
    } else if (Character.isHighSurrogate(c)) {
      if (i + 1 < end && Character.isLowSurrogate(value.charAt(i + 1))) {
        char low = value.charAt(++i);
        int codePoint = Character.toCodePoint(c, low);
        if (count + 4 > buffer.length) {
          flushBuffer();
        }
        buffer[count++] = (byte) (0xf0 | (codePoint >> 18));
        buffer[count++] = (byte) (0x80 | ((codePoint >> 12) & 0x3f));
        buffer[count++] = (byte) (0x80 | ((codePoint >> 6) & 0x3f));
        buffer[count++] = (byte) (0x80 | (codePoint & 0x3f));
      } else {
        writeUtf8ThreeBytes(REPLACEMENT_CHAR);
      }
    } else if (Character.isLowSurrogate(c)) {
      writeUtf8ThreeBytes(REPLACEMENT_CHAR);
    } else {
      writeUtf8ThreeBytes(c);
    }
  }
}
```

Surrogate pairs are correctly decoded across range boundaries with `i + 1 < end`. Furthermore, `write(CharSequence)` was refactored to delegate directly to `write(value, 0, value.length())`, unifying the encoding path.

## 8. Implementation Details: `WriterTemplateOutput` Chunked Range Write

[`WriterTemplateOutput.java`](file:///home/lynguyen/current_source/viet-template-repo/viet-template-runtime/src/main/java/io/github/minh124199/viettemplate/runtime/WriterTemplateOutput.java) optimizes `String` inputs by delegating directly to `writer.write(String, int, int)`. For non-String `CharSequence` inputs, it chunks transfers using a bounded 1024-char buffer:

```java
@Override
public void write(CharSequence value, int start, int end) throws IOException {
  if (value != null) {
    Objects.checkFromToIndex(start, end, value.length());
    if (value instanceof String s) {
      writer.write(s, start, end - start);
    } else {
      int len = end - start;
      char[] buf = new char[Math.min(len, 1024)];
      int srcIdx = start;
      while (srcIdx < end) {
        int chunk = Math.min(buf.length, end - srcIdx);
        for (int i = 0; i < chunk; i++) {
          buf[i] = value.charAt(srcIdx + i);
        }
        writer.write(buf, 0, chunk);
        srcIdx += chunk;
      }
    }
  }
}
```
