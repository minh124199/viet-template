# 04b — VTL Reference Interpreter and Core Runtime Semantics Design

This document details the architectural design, evaluation semantics, scoping models, member resolution policies, defensive limits, space gobbling mechanics, and security controls of the **Viet Template Reference Interpreter** (`viet-template-vtl-interpreter`).

---

## 1. Primary Objectives & Architectural Boundaries

The reference interpreter serves as the authoritative, correctness-first execution oracle for Viet Template. It executes the immutable Abstract Syntax Tree (AST) generated by `viet-template-language-vtl`:

```text
SourceText ──► VtlParser ──► VtlTemplate (AST) ──► VtlInterpreter ──► TemplateOutput
```

### Module Boundaries
- **Module**: `viet-template-vtl-interpreter`
- **Dependencies**: Depends strictly on `viet-template-api`, `viet-template-runtime`, and `viet-template-language-vtl`.
- **Zero Bytecode Generation**: Out of scope for M3. No ASM, ByteBuddy, dynamic class loading, or dynamic linkers (`MethodHandle`/`invokedynamic` polymorphic inline caches).
- **Correctness First**: Acts as the semantic specification against which future compiled/AOT backends (Phases 5–7) will be validated.
- **Strict Isolation**: No Apache Velocity runtime or engine dependencies.

## 2. Evaluation Model and Value Representation

### 2.1 The Three-State Evaluation Model (`EvaluationValue`)
Standard Java `null` is ambiguous in dynamic template engines (it can represent an undefined variable or a variable intentionally set to `null`). Viet Template addresses this with `EvaluationValue`:

```text
               ┌── UNDEFINED    (Variable does not exist in context/scope)
EvaluationValue ┼── DEFINED_NULL (Variable was explicitly assigned or resolved to null)
               └── DEFINED_VALUE(Non-null Java object)
```

- **In Non-Strict Mode (Default)**: Undefined references and defined `null` root references render verbatim as their template source text (e.g. `$user.name` renders as `"$user.name"`, `$nullVal` renders as `"$nullVal"`). In intermediate expressions (e.g. `$obj.nullProp`), dereferencing null evaluates to null/empty.
- **In Strict Mode (`strictReferences = true`)**:
  - Undefined root references (`$missing`) throw a `TemplateRenderException` with source location diagnostics upon output rendering, even when quiet (`$!missing`).
  - Defined `null` references (`$nullVal` or `$probe.nullProperty`) throw a `TemplateRenderException` in normal output, but quiet references (`$!nullVal`) suppress the error and render as empty string `""`.
  - Conditional checks (`#if($missing)`) and alternate-value expressions (`${missing|'fallback'}`) never throw in strict mode for missing or null variables.
- **Alternate Values (`${foo|'default'}`)**: Always evaluated with empty-check enabled (`DuckType.asBoolean(val, true)`), meaning `null`, `""`, `0`, and empty collections trigger the fallback value regardless of `directive.if.empty_check`.
- **Quiet References (`$!foo`)**: Render as empty string when undefined or null (suppressing errors in strict mode for defined nulls).

### 2.2 Scoping & Execution Context (`ExecutionContext` and 0.2.0 `ExecutionFrame`)

#### 0.1.x Baseline Scoping (`ExecutionContext`)
In 0.1.x, `ExecutionContext` manages a nested stack of lexical scopes using standard `ArrayDeque<LocalScope>` while maintaining read-through semantics to the outer immutable `RenderContext`:
- **Root Context**: Read-only wrapper over `RenderContext`.
- **Local Variable Scope**: Pushed by `#set` statements when modifying existing local variables or creating new template-local variables. Each scope maintains a `HashMap<String, EvaluationValue>`.
- **Foreach Scope**: Isolates the loop variable (e.g. `$item`) and loop metadata (`$foreach`). Restores any pre-existing context variables upon exiting the loop.
- **Macro Scope**: Pushes a new frame for macro arguments, ensuring macros do not inadvertently corrupt outer local variables while allowing lexical read-through.

#### 0.2.0 Evolution: Compiler-Assigned Variable Slots (`ExecutionFrame`)
In 0.2.0, the interpreter runtime introduces an optimized `ExecutionFrame` backed by compiler-assigned variable slots (`EvaluationValue[] slots`):
- **Statically Assigned Slots**: During semantic analysis and IR optimization (`O45 AssignVariableSlots`), all statically known variables (template parameters, local `#set` variables, loop counters/items, and macro arguments) are assigned fixed integer slot indices.
- **Branchless $O(1)$ Array Access**: Reading or writing a variable compiles to a direct array load (`slots[slotIndex]`) or store (`slots[slotIndex] = value`), bypassing string hashing, bucket index calculation, and node traversal entirely.
- **Dynamic Fallback Map**: Variables introduced dynamically (via dynamic `#evaluate` evaluations or untyped contributor contexts) fall back to a lazily instantiated `HashMap<String, EvaluationValue> dynamicVariables`.
- **Preservation of 3-State Evaluation Model**: Both array slots and the dynamic fallback map strictly store `EvaluationValue` instances (`UNDEFINED`, `DEFINED_NULL`, `DEFINED_VALUE`). Unassigned slots default to `UNDEFINED`, preserving exact Velocity non-strict literal rendering (`$missing`), strict mode exception triggers, and alternate value fallbacks (`${var|'default'}`).
- **ArrayDeque Preservation**: Scope stacking, macro execution, and layout evaluation continue using `ArrayDeque` to eliminate linked-list pointer overhead and minimize heap allocations.

## 3. Member Access & Method Resolution (`ReferenceAccess`)

Property navigation, index access, and method invocations are managed by `ReferenceAccess` and implemented in `DefaultReferenceAccess`:

```text
$target.property
    ├─ 1. JavaBean getter: getProperty() or isProperty() (case-insensitive fallback)
    ├─ 2. Record component: property()
    ├─ 3. Map key lookup: map.get("property")
    ├─ 4. Public field access: target.property
    └─ 5. Fallback: get("property") method
```

### Method Overload Resolution
When method calls are permitted by the compatibility profile, `DefaultReferenceAccess` scores candidate methods using exact parameter matching, subtyping, and primitive-to-wrapper conversions.

### Control Signal Preservation
Methods invoked from templates that raise or pass control signals (such as `$foreach.stop()`) are detected: `DefaultReferenceAccess` preserves unchecked `ControlSignal` instances without wrapping them in reflection or invocation exceptions.

## 4. Centralized Truthiness Semantics (`VtlTruthiness`)

Viet Template precisely implements Apache Velocity 2.4.1 `DuckType.asBoolean` truthiness rules:
1. **Null / Undefined**: `null` or `UNDEFINED` is **falsy**.
2. **Boolean**: `Boolean.FALSE` is **falsy**; `Boolean.TRUE` is **truthy**.
3. **`getAsBoolean()` check**: If the object exposes a zero-argument `public boolean getAsBoolean()` method, it is evaluated immediately **prior to** empty-check testing.
4. **When `emptyCheck == false`**:
   - All other non-null objects evaluate to **truthy** (including `0`, `0.0`, `""`, empty collections, empty arrays).
5. **When `emptyCheck == true` (Velocity 2.x default)**:
   - **Arrays**: `length == 0` is **falsy**.
   - **`CharSequence`**: `length() == 0` is **falsy** (e.g. `""` is falsy, `" "` with whitespace is truthy).
   - **`Collection` / `Map`**: `isEmpty() == true` is **falsy**.
   - **Custom `isEmpty()`**: Zero-argument method returning boolean (e.g. `isEmpty()` returning true is falsy).
   - **Custom `length()` / `size()`**: Zero-argument method returning numeric size (`0` is falsy).
   - **Numbers**: Checked for zero value! Numeric values representing zero are **falsy**:
     - `BigDecimal.ZERO` (using `compareTo(BigDecimal.ZERO) == 0`)
     - `BigInteger.ZERO` (using `compareTo(BigInteger.ZERO) == 0`)
     - Floating point `0.0f` and `0.0d` (via `Float.compare(f, 0.0f) == 0` / `Double.compare(d, 0.0d) == 0`)
     - Integer/long primitives and wrappers equal to `0`
     - Non-zero numbers (`1`, `-1`, `0.0001`) are **truthy**.
   - **Custom `getAsString()` / `getAsNumber()`**: Evaluated recursively if present.
6. All other non-null objects evaluate to **truthy**.

## 5. Directives & Control Flow

### 5.1 `#set` Directive and Null Semantics
- **Velocity 2.x Default**: `#set` allows `null` right-hand sides (`setNullAllowed = true`). Setting a variable to null or an undefined reference updates/overwrites the target in the local scope with `DEFINED_NULL`.
- **Legacy Velocity 1.x Mode**: When `setNullAllowed = false` (`directive.set.null.allowed = false`), assigning null or undefined leaves the existing variable unchanged.
- **Bare `null` Literal**: Velocity 2.4.1 rejects bare `null` tokens in syntax (e.g. `#set($x = null)` throws a syntax parse error). Viet Template replicates this behavior by default (`BARE_NULL_DISALLOWED`), but allows bare `null` when explicitly enabled via `VtlParserOptions.allowBareNullLiteral(true)`.

### 5.2 Escaping Semantics (`VtlEscaping`)
- Backslash escaping before references follows Velocity 2.4.1:
  - **Defined non-null reference**: Even slashes `2k` reduce to `k` literal slashes followed by evaluated reference; odd slashes `2k + 1` reduce to `k` literal slashes followed by unrendered reference token (`$ref`).
  - **Undefined or Defined-null reference**: Backslash pairs before an undefined/null reference are reduced, but trailing odd slash is preserved: odd slashes `2k + 1` reduce `2k` to `k` leaving `k + 1` slashes followed by `$ref`; even slashes `2k` are preserved verbatim as `2k` slashes followed by `$ref`.

### 5.3 Conditional Branching (`#if`, `#elseif`, `#else`, `#end`)
Evaluates branch conditions with short-circuiting (`&&`, `||`). Executes only the first truthy branch, or the `#else` block if all conditions evaluate to false.

### 5.4 Looping (`#foreach`, `#break`, `#stop`)
- Supports `Iterable<?>`, `Collection<?>`, `Map<?, ?>` (iterates over `.values()`), Java arrays (`Object[]` and primitive arrays), and numeric ranges `[start..end]` (both ascending `[1..5]` and descending `[5..1]`).
- Exposes loop metadata via `$foreach`:
  - `.index`: 0-based iteration index.
  - `.count`: 1-based iteration counter.
  - `.first`: Boolean indicator for first item.
  - `.last`: Boolean indicator for last item.
  - `.hasNext`: Boolean indicator for subsequent items.
  - `.parent`: Nested loop metadata reference.
  - `.stop()`: Aborts loop execution via stackless `BreakSignal`.
- `#break` terminates the current loop immediately.
- `#stop` terminates the entire template rendering process cleanly via stackless `StopSignal`.

### 5.5 Modular Templates (`#include`, `#parse`)
- Resolved via `TemplateResourceResolver` (in-memory, file-system, or custom SPI).
- `#include`: Streams raw resource text verbatim without lexical parsing.
- `#parse`: Evaluates the referenced template AST within the current execution scope, exposing sub-template macros to the caller. Guarded by recursion limits (`maxParseDepth`).

### 5.6 Macros (`#macro`, `#define`)
- **Macro Discovery Pass**: Top-level macro declarations are discovered before template execution, enabling call-before-definition patterns.
- **Default Parameter Expressions**: Trailing parameters can declare default expressions evaluated lazily when callers omit arguments.
- **Block Macros (`#@macro(...) body #end`)**: Body content is captured as an unrendered `RenderableBlock` and bound to `$bodyContent`.
- **`#define($block)`**: Captures an AST block for on-demand lazy rendering.

### 5.7 Dynamic Evaluation (`#evaluate`)
Restricted to the `VTL_DYNAMIC` profile. Dynamically parses and executes runtime strings in the local context, strictly enforced by `maxDynamicSourceLength` and `maxEvaluateDepth`.

## 6. Velocity-Compatible Space Gobbling (`SpaceGobbler`)

In `LINES` mode (the default), Viet Template eliminates whitespace lines that contain only control directive tags and comments:
- Candidate directives: `#if`, `#elseif`, `#else`, `#end`, `#foreach`, `#macro`, `#define`, `#set`, `#break`, `#stop`, and single-line `##` comments.
- **BitSet Character Suppression**: Identified directive lines have their leading indentation, trailing spaces, and trailing newline recorded in an indexed `BitSet`.
- During text node rendering, character indices recorded in the BitSet are omitted directly from the output stream.
- Inline directives (e.g. `Price: #if($sale)$10#else$20#end`) and macro call lines producing textual output retain their whitespace intact.

## 7. Security and Defensive Execution Limits

### 7.1 Security Policy (`VtlSecurityPolicy`)
Prohibits reflection attacks and container escapes by denying property access and method invocations on:
- `java.lang.Class`
- `java.lang.ClassLoader`
- `java.lang.Runtime`
- `java.lang.ProcessBuilder`
- `java.lang.Thread`
- `java.lang.System`
- `java.lang.reflect.*`

### 7.2 Execution Limits (`ExecutionLimits`)
Protects JVM memory and CPU against runaway templates:
- `maxOutputCharacters`: Caps total characters written to `TemplateOutput`.
- `maxLoopIterations`: Caps total iterations across `#foreach` loops.
- `maxRangeSize`: Limits `[start..end]` ranges to prevent OOM allocations.
- `maxMacroDepth`: Guards against infinite macro recursion.
- `maxParseDepth`: Prevents cyclic `#parse` dependencies.
- `maxEvaluateDepth`: Prevents runaway `#evaluate` nesting.
- `maxDynamicSourceLength`: Limits memory spent parsing dynamic strings.

## 8. Differential Semantic Verification (Milestone M3.1)

To ensure the reference interpreter does not encode erroneous semantics prior to M4 differential testing, key semantics were audited and benchmarked side-by-side against Apache Velocity Engine 2.4.1 using `viet-template-tck`:

| Feature Area | Velocity 2.4.1 Baseline Behavior | Viet Template M3.1 Implementation |
| :--- | :--- | :--- |
| **Numeric Truthiness (`empty_check=true`)** | `0`, `0.0`, `BigDecimal.ZERO`, `BigInteger.ZERO` evaluate to **falsy**. | Matches exactly via `VtlTruthiness.isZero(Number)`. |
| **Numeric Truthiness (`empty_check=false`)** | All numbers (including `0`) evaluate to **truthy**. | Matches exactly: non-boolean/non-null objects evaluate to `true`. |
| **`getAsBoolean()` Evaluation Order** | Evaluated **before** `emptyCheck` checks collections or numbers. | Matches exactly: `getAsBoolean()` invoked prior to emptiness check. |
| **`#set` Null RHS** | Allowed by default (`setNullAllowed=true`); overwrites variable with `null`. | Defaults to `setNullAllowed=true`; preserves legacy mode when disabled. |
| **Bare `null` Literal** | Syntax error (`Encountered "null"`). Bare `null` is disallowed. | Rejected with diagnostic `BARE_NULL_DISALLOWED`; opt-in via parser options. |
| **Undefined vs Defined-Null Output** | Undefined and defined-null root variables render verbatim (e.g. `$missing`). | Matches exactly: renders reference text in non-strict mode. |
| **Strict Mode Reference Access** | Missing variable throws upon output rendering even if quiet (`$!missing`). Defined null throws in normal mode, but quiet (`$!nullVal`) renders `""`. `#if` conditionals and alternate values never throw. | Implemented with separate checks for undefined root references vs defined nulls; suppresses quiet defined nulls; protects `#if` and alternate values. |
| **Alternate Value Fallback** | Always performs empty check (`DuckType.asBoolean(val, true)`), evaluating `0`, `""`, and empty collections to fallback. | Matches exactly: passes `true` for empty checking regardless of engine-level `emptyCheck`. |
| **Backslash Reference Escaping** | Odd backslashes before undefined/null references reduce pairs to single slashes and preserve trailing slash. | Matches exactly: odd slashes halved and rounded up, even slashes preserved intact. |
